# AWP 成長戦略: 1年で100万ユーザー（計画 v2026-10-08）

## 0. 前提と正直な見立て
- 目標: 2026年10月28日の公開から1年（2027年10月末）で **登録ユーザー100万人**。日本の新規プラットフォームとしては非常に高い目標。達成の鍵は「広告で買う」ことではなく、**プロダクトに組み込まれた獲得の仕組み（ループ）**が回るかどうか。
- 数字はすべて計画値・仮定。実績と計画の差は毎週 data が報告し、CEO が重点を組み替える。
- 制約: 事実でない表示・誇張をしない（景品表示法・ステマ規制）。お金に関わる機能は弁護士の確認を優先する。AI費用は各プランの利用枠（料金の78%）で上限が決まる設計を守る。

## 1. AWPが勝てる理由（ポジショニング）
日本の若いクリエイター・個人事業主向けに「スマホだけで、AIとおしゃべりして、ページ・予約・商品・収益化まで無料で始められ、そのままSNSのようにつながれる」場所。既存サービスは「ページ作成」「SNS」「予約」「EC」がばらばらで、無料で始めると機能が足りない。AWPは **無料で全部そろい、手数料0円の直接払い、報酬の78%還元** で差別化する。

## 2. 獲得の仕組み（4つのループ）
1. **ページ・ループ**: 公開ページの下に「Made with AWP」と作った人のプロフィールが付く。ページを見た人（来店客・ファン）がAWPを知る。→ 指標: ページ閲覧数、バーからの登録率。
2. **SNS・ループ**: プロフィール・発見・タイムライン・フォロー。登録した人が他の人を見つけ、投稿がSNSで共有される。→ 指標: 7日アクティブ率、フォロー数、共有数。
3. **紹介・ループ**: 招待した人・された人の両方にキャッシュ（AWP内で使える）を付与する紹介プログラム（実装: growth が設計、engineering が実装、legal が確認）。→ 指標: 紹介経由の登録比率、k値。
4. **エコシステム・ループ**: Harness（LINE/X/IG）・提携ツール・直接払いショップ・予約。「お店の道具」として毎日使われることで定着し、お客様側も訪問者としてAWPに触れる。→ 指標: 予約・注文件数、Harness接続数。

## 3. 四半期ごとの計画値（累計登録・仮定）
| 期間 | 累計登録（計画） | 主な打ち手 |
|---|---|---|
| 2026/10〜12（Q1） | 5,000 | ベータ→公開。初期の50〜100人の「核」のクリエイター・店舗を手厚く支援。紹介プログラム、OGP、オンボーディング、使い方ガイド。SNSで事例紹介（事実のみ） |
| 2027/1〜3（Q2） | 50,000 | ページ・ループの改善（バーの登録率）、PWA/アプリストア、SEO（UGCページのインデックス）、提携先の拡充、キャンパス・地域コミュニティとの連携 |
| 2027/4〜6（Q3） | 250,000 | 紹介ループの最適化、クリエイター向けの収益化事例（確定した報酬だけを公開）、Harness連携の普及、インフルエンサー協業（PR表示） |
| 2027/7〜10（Q4） | 1,000,000 | 多言語化（英語→アジア）、API/連携の開放（拡張性）、法人・自治体との提携、広告は投資回収が確認できた経路にだけ |

計画値は「各四半期で前期の5〜10倍」。これは紹介・ページの2つのループが k ≥ 0.5 で回り、7日アクティブ率が 30% 以上を保つという仮定に基づく。これを下回る場合は、拡大ではなく **定着（アクティベーション・継続）** に重点を戻す。

## 4. 収益と費用（単位経済・計画の式）
- 収入: 有料プラン（料金の22%が運営分、78%はその人のAI利用枠）/ 確定報酬の22% / Harness導入支援 / 独自ドメイン（有料プランへの転換）。直接払いショップは手数料0円（獲得・定着のための機能）。
- 費用: AI（最大の変動費）、インフラ、人件費（少人数）、決済は使わないため決済手数料なし。
- **最重要のリスク: 無料プランのAI利用枠**。無料枠（既定 $1.5/月 ≒ ¥225）× 100万人 × 利用率 が費用の上限。利用率10%でも月 ¥2,250万。対策: (a) 無料枠は小さく保ち、無料利用者には速いモデル（Haiku）を使う、(b) 利用枠を「使った分だけ」計上する現行の計測を維持、(c) 無料枠の原資を提携報酬・PR枠の収益で賄える範囲に毎月調整（finance が毎週報告、propose_plan_config で提案）。
- 判断の指標: 利用者1人あたりの月のAI費用 / 有料転換率 / 1人あたりの提携・PR収益。粗利がマイナスの経路は拡大しない。

## 5. サービスを提供し続けるための基盤（信頼性・拡張性）
- いま: Render（Web×2 + Postgres）。10万人規模までに: 画像をDBからオブジェクトストレージへ、重い処理（デザイン生成・AI）をキュー化、DBの読み取り分離、CDN、監視とアラート（実装済みの #🚨-アラート を拡張）。
- 100万人規模: マルチリージョン・自動スケール・レート制限の強化・バックアップと復旧訓練。engineering と security が四半期ごとに点検し、必要な実装を request_implementation で依頼する。
- 拡張性: 機能はモジュール（予約・商品・チャットボット・収益化・Harness）として追加できる構造を維持。外部連携は提携ツールカタログ＋Harness連携の型で増やす。

## 6. 運営体制（AI企業）
- 人間のオーナー: 目標・制約・重要な判断（お金・法律・大きな方針）。承認待ちの操作は管理画面「AI企業」と Discord #🏢-AI企業 に届く。
- CEO（日次）→ COO（分解・配分）→ 専門エージェント（調査・プロダクト・開発窓口・QA・データ・マーケ・コンテンツ・グロース・CS・財務・提携・セキュリティ・法務）→ 監査役（独立して検証）。
- 実装は GitHub 上の Claude Code → レビュー → オーナーのマージ。公開投稿・料金変更・提携カタログの変更は人間の承認。
- 毎週月曜: 財務・データの週次報告と監査。CEO はこれを元に四半期計画の修正を提案する（提案はオーナーに報告し、承認後に company/strategy を更新する）。
