## 1. サービス概要

- **AWP（Actualize World Peace）**: スマホでホームページ（ランディングページ。以下「ページ」）を作り、無料で公開できるWebサービス／スマホアプリ。日本の若いクリエイター・事業者向け。
- 構成: バックエンド（Express + PostgreSQL）、フロントエンド（Next.js）、スマホアプリ（Expo。別リポジトリ・この資料の対象外）。本番は Render（有料プランのWebサービス2つ＋PostgreSQL）で稼働（`render.yaml`）。サーバーの所在国・リージョンは **未確認**（`render.yaml` に指定なし）。
- 利用者（ページの持ち主）が登録・公開する内容: ページの文章・写真、予約リクエストの受付、商品の掲載と注文の受付（直接払いショップ）、プロフィール・投稿（SNS機能）、LINE公式アカウントとの連携、AIチャットボット、収益化（PR枠）。
- 訪問者（ページを見る人）は、ログインなしで、ページの閲覧・予約リクエストの送信・注文・AIチャットボットへの質問・通報ができる。
- 利用者のアカウント作成には、日本の携帯電話番号（070・080・090）のSMS認証が必要（`backend/src/routes/auth.ts`。SMS設定が「未設定」の環境では免除される実装。本番設定は運営者が確認）。1つの電話番号で作れるアカウントは1つ。
- 運営の自動化: AIエージェントが運営の一部（SNS投稿の下書き作成、エラーの診断、開発の進行など）を行うが、**本番への反映は運営者のPRのマージだけ**、自動投稿は **既定でオフ**（`User.autoPublishEnabled` の既定値 false）。詳しくは §8。

### 2-3. セキュリティ上の事実

- 暗号化している: Harness のAPIキー、出品者およびAWPの振込先口座、Discord Webhook（AES-256-GCM。鍵は環境変数 `SECRET_ENCRYPTION_KEY`、未設定なら `JWT_SECRET` から導出）。
- 暗号化していない: LINEのチャネルシークレット／アクセストークン、SNS連携のトークン、写真・投稿画像。
- ログイン後のAPIは JWT。管理者フラグはDBの直接操作でのみ設定でき、登録APIからは設定できない。
- ボット対策: 予約フォームの不可視入力欄、ページ／全体ごとの回数制限（メモリ上の簡易方式。再起動でリセット）。
- 決済: クレジットカード情報は扱わない（Stripe のホスト型決済のみ）。直接払いショップは代金を預からない。

### 2-4. 公開されるもの

プロフィール、投稿、公開ページの内容、出品者の特定商取引法表記。通報で運営者が非公開にできる（`hidden`）。

### 2-5. アカウント削除の実装（要確認の論点）

`DELETE /api/auth/account` は、Stripe の定期課金があれば先に解約し（解約できなければ削除を中止）、その後、問い合わせ・ページ・LINE連携・ユーザー本体を1つのトランザクションで削除します。

- ページを削除すると、写真・予約・商品・注文・閲覧記録などは連鎖削除される。
- 一方、`SocialAccount` `ScheduledPost` `AgentTask` `AutomationWorkflow` は、マイグレーション上 `User` への外部キーが `ON DELETE RESTRICT` で、削除コードがこれらを先に消していない。**これらのデータを持つ利用者では、削除が外部キー違反で失敗する可能性がある**（コードの読み取りによる指摘。実機での再現は **未確認**）。
- 台帳（`LedgerEntry` ほか）と `RevenueEvent`、`AffiliateClick`、`Report` は削除されない。利用規約は「未使用のキャッシュは失効」と書いている（第5条の2）が、残高の失効を台帳に記録する処理は **コード上確認できなかった**。
- プライバシーポリシー第5条は「アカウントと関連データを削除できる」と書いている。上記との整合を §10 で確認したい。

## 4. 収益化とキャッシュの仕組み

### 4-1. 収益化（PR枠）

- 利用者がページごとに「収益化（PR枠）」を **オン** にした場合だけ、「PR」と表示した提携サービスの紹介枠が出る。**既定はオフ**（`LandingPage.monetizationEnabled` の既定値 false）。
- 提携ツール（`ToolCatalogItem`）は運営者が登録する。報酬の分配が許されない案件（ASPの規約）は `revenueShareAllowed = false` で分配できない。
- クリックは `AffiliateClick` に数だけ記録（個人を特定しない）。

### 4-2. 収益の記録と 78 / 22 の分配

1. ASP・広告主の管理画面で報酬が **「確定」** したものを、運営者が管理画面で記録する（発生ベースでは数えない）。同じ成果ID（`externalRef`）は二重記録できない。
2. 記録時に、ページの持ち主へ **78%**（`OWNER_SHARE_PERCENT = 78`、**円未満切り捨て**）、AWPへ **22%**（端数はAWP側）を分配する。ページの無い「AWP自身の紹介」は全額AWP。
3. 分配は、(a) 提携ツールが `revenueShareAllowed`、(b) 持ち主が収益化オン、の両方を満たすページだけ。
4. 台帳は **複式簿記** で、借方合計＝貸方合計の取引だけ記録できる（`backend/src/lib/ledger.ts`）。
   - 記録: 受取予定（資産）／AWPの収益／利用者のキャッシュ（AWPから見た負債）。
   - 記録済みの取引は書き換えず、ASP側で否認・取り消しされた場合は **逆仕訳** で打ち消す（分配したキャッシュも戻る）。
5. 利用規約（第5条の2）に、同内容（78%、切り捨て、取り消し、不正クリックの扱い）を記載済み。

> 「78」という数字は **もう1か所**、有料プランの料金の内訳にも出てくる: 料金の78%をその利用者のAI利用枠に充て、22%をAWPの取り分とする（`backend/src/lib/plans.ts` の `AI_SHARE = 0.78`）。これは収益化の分配（PR枠）とは **別の仕組み** なので、混同しないよう注意。

### 4-3. キャッシュの使い道（AWP内の支払いのみ）

- 利用者に付与されたキャッシュで払えるのは、実装上、次の2つだけ：
  - Harness導入支援の代金（`POST /api/wallet/pay/harness/:orderId`。申し込みを取り消すと逆仕訳で返金）
  - AWPの有料プランの代金（`POST /api/plans/…` の支払い方法 `cash`。即時有効化）
- 他の利用者への送金・譲渡・換金・購入（チャージ）の機能は **コード上存在しない**。利用規約（第5条の2）も「有料機能の代金の支払いにのみ使用でき、現金・他社ポイントへの交換、譲渡・貸与、金銭での購入はできない」と記載。
- 残高の二重利用を防ぐため、支払い時は利用者の行をロックしてから残高を確認する。
- 有効期限・失効の処理は **コード上確認できなかった**（規約は「アカウントを削除した場合、未使用のキャッシュは失効」と記載）。

### 4-4. 出金は準備中

- `GET /api/wallet` は常に `withdrawal.available = false`、理由「出金（銀行振込）は準備中です」を返す。出金のAPI・画面は **存在しない**。
- 規約は「本人確認・税務・送金の手続きが整い次第提供」と記載。
- 論点: キャッシュが資金決済法上の前払式支払手段にあたるか／出金開始時の資金移動業・源泉徴収・本人確認・税務（§10）。

### 4-5. 有料プランの課金

- 月額プラン（ライト／スタンダード／プロ）。料金は「Claude Pro の月額（米ドル）を基準にした倍率×為替」から算出し、管理画面で変更できる（`plans.ts`）。
- 支払い方法: **銀行振込**（運営者が入金を確認して有効化。振込期限14日。AWPの振込先は暗号化して保存）、**キャッシュ**、および Stripe の月額課金（`backend/src/routes/billing.ts`）。
- プランを変更するときは、残り日数を金額換算して新プランに加算する（`activatePlan`）。

### 4-6. 直接払いショップ

- 代金は購入者から出品者へ直接（銀行振込・店頭／手渡し）。AWPは代金を預からず、手数料も取らない。
- 出品者が **特定商取引法の表記をそろえないと販売を始められない**（必須項目が空だと「足りないもの」を返して拒否）。
- 在庫・支払い期限（既定7日）・状況の管理はAWP、売買契約の当事者は出品者と購入者（規約第5条の3）。

## 5. 予約リクエスト

- 訪問者が、メニュー・希望日時・お名前・連絡先（メールまたは電話）・メッセージを送る。**決済は扱わない。**
- 送信の条件: お名前必須、連絡先の形式チェック、希望日時が持ち主の設定範囲（最短何日後〜最長何日後）内、**「個人情報の取り扱いへの同意」必須**。1ページ1日50件まで（持ち主が管理者でない場合）。
- 持ち主へプッシュ通知（お名前・日時・メニュー）。持ち主が「確定」「お断り」と一言メモを返す。訪問者は受付番号で状況を確認でき、取り消しもできる。**状況確認画面には連絡先・お名前を出さない。**
- 「予約が確定した」と見えるのは持ち主が確定したときだけ。AIチャットボットは予約を受け付けたり確定したりしない（システムプロンプトで禁止）。
- 保存期間: 希望日から365日（§2-2）。取り扱いの責任は「各ページの運営者」とプライバシーポリシーに記載。

## 6. 広告・表示に関する運用（景品表示法・ステルスマーケティング）

- 提携リンクは「PR」と表示（収益化の枠、提携ツール一覧）。利用規約第5条にも記載。
- AIに事実を作らせない方針（`CLAUDE.md`）：実績・口コミ・限定特典・数字は **ユーザーが登録した事実以外を生成・表示しない**。
  - 対話ビルダー：事実ごとに出どころの状態（本人が伝えた／本人が確定／AIの推測／既定値／未確認）を持ち、**公開に使うのは「確定」と「既定値」だけ**（`BuilderSession` のコメント、`PUBLISHABLE`）。
  - LINE自動応答・チャットボット：登録済みの事実だけで答え、書かれていない料金・在庫・期限・実績を作らないよう指示。事実だけで答えられないときは「担当者からご案内します」等と答える。
  - ただし、これらはAIへの **指示** であり、AIの出力が常に守られる保証はない（出力の事後検査は、SNS下書きのコンプライアンス審査を除き **未確認**）。

## 7. AIの利用箇所

利用者の操作から始まるAIは、利用者のプランごとの月の利用枠（`AiUsage` の見積額）で管理され、枠を超えると、チャットボットは「いまはAIでお答えできません」、LINE応答は定型文に切り替わる。

| 機能 | 使うAI | 入力される情報 | 出力の使われ方 |
|---|---|---|---|
| ページ作成の対話ビルダー | Claude | 利用者との会話、事実の台帳 | 事実の整理、文案。**公開は本人が確定した事実のみ** |
| ページのデザイン作成・審査 | Claude、画像：Gemini／Cloudflare | 事業名・キャッチコピー・強みなど、生成したメイン画像（審査用） | 配色・書体・レイアウト、メイン画像 |
| セクション（機能）の文章作成 | Gemini（指示文作成）→ Claude（本文） | お店の基本情報、お店から預かった回答 | ページの各セクション。数字・実績を新たに作らないルールつき |
| AIチャットボット（訪問者向け） | Claude（Haiku 系） | **訪問者の質問（直近8往復・各500字まで）**、ページの掲載情報 | 回答。質問文のみ90日保存 |
| LINE自動応答 | Claude | 受信メッセージ（500字まで）、ページの登録事実 | LINEへの一次返信。失敗・APIキー無しは定型文 |
| SNS投稿の下書き（マーケティング担当） | Cloudflare Workers AI（Qwen） | 事業の情報 | 下書き。**既定は人の承認待ち** |
| SNS投稿の審査（コンプライアンス担当） | Claude | 下書き、事業名・キャッチコピー・強み | 承認可否。**本人が自動公開をオンにし、審査に通った場合だけ自動で予約**（既定オフ） |
| 成長分析（A/Bテスト等） | Claude 等（`agents/growth.ts`） | 閲覧・クリックの集計 | 優劣の判定・提案。詳細は **コード未精査** |
| エラー診断（監視担当） | Claude | エラーの発生元・メッセージ・スタック・付随情報 | 診断文。**自動修正はしない** |
| AIオペレーター（管理者のチャット） | Claude | 運営の概況（個人情報を含まない） | 提案。**運営者が承認したときだけ実行** |
| AI企業（CEO以下の自律運営） | Claude（役割ごとにモデルを使い分け） | 運営の指標、メモリ | タスク・提案。高リスクの操作は人の承認待ち（`registry.ts`）。**初期状態は停止** |
| ローンチ・クルー（Discordの開発チーム） | Claude | 運営の進行情報 | GitHubへの課題登録→Claude Codeが実装→PR。**本番反映は運営者のマージのみ** |

- AIが利用者データを「学習に使うか」「どこに保存されるか」は、各社との契約・設定による（コードからは判断できない）→ 運営者が確認し、プライバシーポリシーに反映する。
- AI生成物の著作権・利用者への権利帰属は、利用規約の記載を弁護士に確認したい（本資料は規約の全文を精査していない）。

## 8. 運営の自動実行と緊急停止

- 自動で動く処理：6時間ごとのAIエージェント、SNS予約投稿の送信、AI企業、ローンチ・クルー、注文の期限切れ掃除（10分ごと）。
- 方針：自動実行は既定でオフ／人の承認つき。
- 緊急コントロール（管理画面）で、AIエージェントの定期実行、SNSの予約投稿、ローンチ・クルー、AI企業を即時に止められる。運用は `docs/launch/runbook.md` §5。

## 9. 利用者保護・通報・権利侵害への対応

- ページ・プロフィール・投稿の **通報** 機能（違法・詐欺・アダルト・嫌がらせ・著作権・その他）。運営者が管理画面から **非公開**（公開URL・発見・サイトマップから外れる）にできる。

- 予約者・購入者の個人情報は、ページの運営者（出品者）の責任で扱う旨をプライバシーポリシーに記載。

## 10. 弁護士に確認してほしい論点

1. **キャッシュの法的性質**：「報酬の78%を付与、AWPの有料機能にのみ使用可、換金・譲渡・購入不可」の設計は、資金決済法の前払式支払手段（自家型）に該当しないと整理できるか。ポイント・景表法上の景品類との関係。
2. **出金開始時**：出金（銀行振込）を始める場合の資金移動業の要否、本人確認、源泉徴収・支払調書、インボイス（適格請求書）の整理。
3. **PR表示・ステマ規制**：「PR」表示の位置・文言が十分か。利用者のページに掲載する広告の責任分担。
4. **アフィリエイト報酬の再分配**：ASPの規約が第三者への分配を許すか（コードは `revenueShareAllowed` で案件ごとに制御）。
5. **個人情報保護法**：
   - 予約者・購入者の情報を、AWPが保存し、ページ運営者（持ち主）が利用する関係（委託か共同利用か／責任分担）。
   - 外国の事業者（Anthropic・Google・Cloudflare・Twilio・Stripe・Expo・Render）への提供・委託の記載（越境移転の同意・情報提供）。
   - 保存期間（予約365日、注文400日、チャット90日、問い合わせ・閲覧記録は自動削除なし）の妥当性と、削除が「新しい受付時」に走る実装の扱い。
6. **アカウント削除とポリシーの整合**（§2-5）：削除対象に台帳・収益記録・通報が含まれないこと、削除が失敗しうる点。公開前に実装を直すか、文面で補うか。
7. **平文保存**：LINEのチャネルシークレット／アクセストークン、SNSトークンの平文保存を、公開前に暗号化すべきか（安全管理措置の観点）。
8. **利用規約・特定商取引法に基づく表記（`/legal`）・プライバシーポリシー**の【】を埋めるための必要事項と、全体のレビュー。
9. **AI生成物**：誤情報（実績の捏造など）への責任、利用者の確認義務の書き方、AIと対話した内容の取り扱い、未成年の利用。
10. **ショップ**：出品者の特商法表記の必須項目、「請求があれば開示」の運用が法令に合うか、プラットフォーム運営者としての責任範囲。
11. **通報への対応**：削除要請・プロバイダ責任制限法に沿った対応フロー、窓口と対応時間。
