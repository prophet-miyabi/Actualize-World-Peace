# Auto-Sales-Agent — プロジェクトルール

クラウドワークス・ランサーズ等の案件テキストから、見込み客専用の「動くモックアップ」と「個別提案文」を半自動で作り、公開URL付きで営業するための作業場所。Claude Code がこのフォルダで作業するときは、必ずこのルールに従う。

## 全体フロー（/pitch が実行する順）

1. **取り込み** `input/<案件ID>/job_post.txt`（または `job_url.txt`）。`node auto-sales-agent/scripts/new.js "<案件名>" [URL|テキストファイル]` で雛形を作る。
2. **分析** `input/<案件ID>/brief.json` を `schema/brief.schema.json` の形で書く。案件文に書かれていないことは `assumptions` に分け、`facts` と混ぜない。
3. **生成** `node auto-sales-agent/scripts/generate.js <案件ID>` → `dist/<案件ID>/index.html`。その後、Claude Code が HTML を開いて **その業界・その会社らしく** 仕上げる（文言・ダミーデータ・色・並び）。
4. **デプロイ** `node auto-sales-agent/scripts/deploy.js <案件ID> [awp|cloudflare|vercel]` → 公開URLを `input/<案件ID>/deploy.json` に保存。
5. **提案文** `node auto-sales-agent/scripts/propose.js <案件ID>` → `output/<案件ID>_proposal.md`。Claude Code が案件文に合わせて最終調整する。

## モックアップの品質基準（これを満たさないものは出さない）

- **触って動く。** ボタン・タブ・モーダル・検索/絞り込み・ステータス変更・フォームの入力ステップ・トースト通知のうち、案件に関係するものが少なくとも5つ動く。Alpine.js（CDN）かバニラJSで、1ファイルで完結させる。
- **その会社の画面に見える。** 屋号・業界用語・商品名・スタッフ名・地域名・単位（「件」「席」「枠」「号室」など）を最初から反映する。ダミーデータは業界で実際に使う言葉で、10〜30件。`Lorem ipsum`・「サンプル1」は禁止。
- **美しい。** Tailwind CSS（CDN）。余白は8の倍数、見出しの階層が明確、色はメイン1色＋アクセント1色＋グレー階調。角丸・影・境界線は全体で統一。日本語フォントは `Noto Sans JP`（Google Fonts）。
- **スマホで崩れない。** 375px 幅で横スクロールが出ない。業務画面はスマホではカード表示に切り替える（テーブルの横スクロールだけに頼らない）。PC は 1280px で余白が間延びしない。
- **軽い。** 外部読み込みは Tailwind CDN・Alpine.js CDN・Google Fonts のみ。画像は SVG か CSS グラデーションで代替（写真を使う場合は `https://images.unsplash.com` の無料写真に限り、人物の顔のアップは避ける）。
- **事実を作らない。** 実績件数・顧客の声・受賞・「No.1」などは、案件文に書かれていない限り入れない。数字が必要な場所は「◯◯件（見本）」と明示するか、ダミーデータであることが分かる見出しにする。
- **見本であることを明示。** 画面右下に小さく「プロトタイプ（見本データ）」のバッジを置く。個人情報・実在の人名は使わない。
- **動作確認してから渡す。** ブラウザ（375px / 1280px）で開き、コンソールエラーがないこと、主要な操作が動くことを確認する。

## 提案文のライティングルール

- **1行目はキラーフレーズ。**「ご提示の要件をもとに、すでに御社専用のプロトタイプ（動く画面）を作成しました。」→ 2行目に公開URL。
- **案件文の言葉を使う。** クライアントが書いた課題・用語をそのまま引用し、「それをこう解決する」と対応づける（箇条書き3〜5点）。
- **プロトタイプで確認できることを具体的に。**「スマホで開いて、◯◯ボタン → ◯◯ をお試しください」と操作を1〜3個案内する。
- **提案の構成は固定。** ①キラーフレーズ＋URL ②要件の理解（引用→解決） ③プロトタイプで確認できること ④本番で追加・変更すること（認証・DB・決済・外部連携など） ⑤納期と費用（幅で提示。既定は `plan.json` の標準価格） ⑥保守・サポート（契約書類一式があることに触れる） ⑦次の一歩（30分のオンライン打ち合わせ候補を2つ）。
- **長さ。** 本文 600〜900字。見出しは使わず、段落と箇条書きで。絵文字は使わない。
- **言ってはいけないこと。** 根拠のない実績・導入社数・満足度、「必ず」「絶対」、競合の悪口、値引きの先出し。人工知能の略語（英字2文字）は使わず、「自動化」「仕組み」と言う。
- **自分の立場。** 個人事業主（AWP）として、契約書・保守SLA・セキュリティ基準書が用意されていること（`contracts/`）を強みとして一言添える。

## 画像を入れる前の手順（必須）

画像（Runway などの生成・写真）を LP に組み込む前に、**「どんな画像を入れるか」の構成案を必ず3つ提案し、オーナーに選んでもらってから生成する。** 各案は次の形で書く。

1. 案の名前と狙い（誰の、どの不安・欲求に効くか）
2. セクションごとの画像の役割・被写体・雰囲気・色調・配置（スマホで切れても主題が残るか）
3. 写真／イラスト／図表／画面キャプチャのどれにするか、その理由
4. 使わない画像（汎用のストック写真・握手・笑顔の集合・意味のない風景）を明示

「業種に関係がある」だけの画像は入れない。セクションの目的（信頼・行動・世界観）に効く被写体だけを選ぶ。生成後は文字・ロゴ・人物の顔の混入を目視で確認し、混入したものは作り直す。

## 案件IDの付け方

`YYYYMMDD-<媒体>-<短い英数字>`（例: `20261021-cw-fujijusetsu`）。フォルダ名・URLのパスになるので半角英数字とハイフンのみ。

## デプロイ先の既定

既定は `awp`（`frontend/public/demos/<案件ID>/` にコピーして git push → `https://awp-frontend-bf17.onrender.com/demos/<案件ID>/`。Render の自動デプロイで 3〜5 分後に公開）。Cloudflare Pages / Vercel は CLI とトークンがある環境でだけ使う（`deploy.js` が無ければ案内して止まる）。公開URLに顧客の社名を含めない（案件IDは短い英字で）。

## 禁止事項

- 案件文に含まれる個人情報（氏名・電話・メール）を `dist/` や提案文に転記しない。
- 既存の AWP 本体（backend / frontend/src）を /pitch の作業で変更しない。触ってよいのは `auto-sales-agent/` と `frontend/public/demos/` だけ。
- 顧客の本番データ・認証情報を扱わない（プロトタイプはダミーデータのみ）。
